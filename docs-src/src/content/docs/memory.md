**Learn lane · Mission: correct once, carry the lesson forward**

Memory is learned knowledge worth recalling beyond the current session. It helps the
next session start ahead without pretending historical guidance is the same as current
truth.

## What belongs in memory

| Kind | Example |
| --- | --- |
| Preference | "Use concise customer-facing language; keep internals in Reference." |
| Decision | "Collections is the canonical saved-material destination." |
| Lesson | "A mocked persistence test hid a broken migration; use a real database here." |
| Project motivation | "The rewrite is driven by compliance, not cosmetic cleanup." |
| Reference | "Delivery incidents are tracked in the OPERATIONS project." |

A strong memory includes the reason, when it applies, and enough provenance to judge it
later.

## What memory does not replace

### Concept boundary

- **AGENTS.md:** standing rules every agent should follow.
- **Project files/source systems:** authoritative current state.
- **Work plan:** unfinished shared intent.
- **Session history:** supporting evidence and chronology.
- **Memory:** learned knowledge that may help interpret the next situation.

Do not copy repository architecture, current task status, or readily discoverable source
facts into memory. Do not store secrets; store only a safe reference to the approved
credential location when that reference is useful.

## Save at the moment of learning

When you correct a recurring misunderstanding or confirm a non-obvious decision, ask
the agent to remember it. The saved record should explain why:

> Use real persistence in integration tests. A mocked test once passed while the
> production migration was broken. Apply this to any test that claims database proof.

A bare rule can be followed off a cliff. The reason helps a future agent handle edge
cases.

## Recall before rediscovery

Relevant memory can be supplied when a new request matches it. The agent should use the
recalled lesson, cite its source when important, and verify mutable facts before taking
consequential action.

Memory is not omniscient and should not silently override observed reality. If the
project or external system has changed, current authoritative state wins.

## Correct and forget deliberately

When a memory becomes wrong, supersede or remove it rather than leaving two conflicting
claims. Ask to forget information that should no longer be retained. Sensitive material
should never have been stored as ordinary memory in the first place.

## Mission complete when

Start a later session with a related ordinary request. The relevant lesson should be
available without you repeating it, and the agent should still verify any mutable live
fact before acting.
