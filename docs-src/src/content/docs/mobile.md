**Learn lane · Mission: move the judgment surface with you**

Mobile is a client for the same Axis node and durable work—not a separate cloud copy or
read-only status application. It is most useful for reviewing, steering, approving,
and taking over short human steps while deeper execution remains on the host.

## Connect to your node

First pair the mobile client with the Axis node you own through the supported
[remote-access](/docs/remote-access/) flow. The host must remain powered, awake enough to
serve Axis, connected to the configured network, and running Axis.

Pairing remembers the chosen node. Do not publish screenshots containing node names,
addresses, pairing codes, QR codes, session identifiers, or private project data.

## Continue the same work

From mobile you can:

- read the complete rendered session and its Working/Worked evidence,
- send a new request or queue a follow-up,
- answer a question or scoped approval,
- review a Collection item,
- begin a new session in a project or workstream,
- dock and take over a browser when human interaction is required.

The session identity should stay the same across devices. A device handoff must not
create a replacement transcript.

## Use the composer normally

The mobile composer supports ordinary text, attachments, images, model/effort selection,
voice input where available, Send, and Stop. Staged images should open at useful full
resolution for review rather than only displaying the small tray thumbnail.

Busy-session follow-ups use the same steering queue as desktop.

## Navigate around the work, not away from it

Responsive layouts may use session cards, drawers, and full-screen panes, but the
underlying owner remains the session. An Inbox item should open its exact interaction;
a browser takeover should use the same live browser; a Collection item should retain
its source link.

## Protect battery and attention

Hidden terminal, browser, preview, and transcript surfaces should suspend rendering or
polling when they are not visible. Reduced-motion settings should be respected. Axis
does not need sound effects or completion chimes; opt-in notifications can surface
work that genuinely needs you.

## Understand the offline boundary

Durable state helps the interface recover after a connection loss, but active execution
still happens on the host. If the host sleeps, shuts down, loses its network, or stops
Axis, mobile cannot make that node continue working until it is reachable again.

## Mission complete when

Open a session on desktop, review and answer one real checkpoint on mobile, then return
to desktop and confirm the same session, decision, and evidence are present.
